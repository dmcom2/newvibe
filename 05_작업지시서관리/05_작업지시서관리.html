📌 WO (Work Order)

작업지시서. 생산계획팀이 현장 작업자에게 내리는 지시 문서 한 건

📌 지시번호 자동 채번

WO-YYYYMM-001 형식으로 발행 순번을 자동 생성

📌 progPct (진행률)

생산완료수 ÷ 지시수량 × 100 — 진행률 바의 폭(width)을 결정

📌 D-Day

납기일까지 남은 일수. (dueDate - today) / 86400000로 계산

📌 STATUS_META

대기·진행중·검사중·완료·보류 5개 상태의 라벨·색상을 담은 객체

📌 editId (모달 재사용)

null이면 신규 등록, 값이 있으면 수정 모드로 같은 모달을 재사용

🌱 낯선 용어가 나와도 괜찮습니다. 코드는 AI가 쓰고, 우리는 읽고 요청만 하면 돼요!

핵심 기술 ① — WO 데이터 구조 & 지시번호 채번

모든 카드·계산의 출발점이 되는 작업지시서 객체와 자동 번호 생성
// WO(Work Order) 데이터 구조 const wo = { id: 1001, no: 'WO-202606-001', // 지시번호 (자동 채번) issueDate: '2026-06-01', customer: '(주)삼성전자', product: 'PCB-A2401', layer: '4층', qty: 1000, // 지시 수량 produced: 650, // 생산 완료 수량 line: '1호기', dueDate: '2026-06-10', status: 'progress', currentStep: '에칭', }; // 지시번호 자동 채번 function generateWONo() { const now = new Date(); const ym = now.getFullYear() + String(now.getMonth() + 1).padStart(2, '0'); const seq = orders.filter(o => o.no.includes(ym)).length + 1; return `WO-${ym}-${String(seq).padStart(3, '0')}`; // 예: WO-202606-001 }
💡 필드 하나하나가 카드 렌더링에 그대로 매핑됩니다 — qty/produced로 진행률, dueDate로 D-Day, currentStep으로 공정 버튼 활성화를 계산합니다.

핵심 기술 ② — 공정 단계 선택 버튼

배열 → 버튼 렌더링 → 클릭 시 currentStep 갱신, 하나의 흐름으로 이어지는 패턴
1

공정 배열 정의

const PROCESS_STEPS = ['재단','천공(드릴링)','에칭','도금','표면처리','외관검사','전기검사','포장'] — 8단계를 배열로 고정합니다.

2

버튼 렌더링

PROCESS_STEPS.map(step => ...)으로 각 단계를 버튼 HTML 문자열로 변환해 한 번에 삽입합니다.

3

활성 상태 표시

현재 currentStep과 일치하는 버튼에만 active 클래스와 하늘색 배경을 부여합니다.

4

클릭 시 갱신

버튼의 onclick="selectStep('${step}')"이 WO의 currentStep을 바꾸고 카드를 다시 그립니다.

핵심 기술 ③ — 진행률 계산 & 시각화

생산완료수 하나만 바뀌어도 카드 전체 진행률 바가 즉시 반응
// 진행률 = 생산완료수 / 지시수량 × 100 const progPct = wo => wo.qty ? Math.round(wo.produced / wo.qty * 100) : 0; // 진행률 바 HTML `<div class="progress-bar"> <div style=" width: ${progPct(wo)}%; background: ${progPct(wo) >= 100 ? 'var(--green)' : 'var(--sky)'}; "></div> </div>`
💡 produced 값을 입력할 때마다 progPct()가 재계산되어 진행률 바 폭(width)이 실시간으로 바뀝니다. 100% 도달 시 색상도 초록으로 전환됩니다.

핵심 기술 ④ — 납기 D-Day 계산

밀리초 차이를 "일" 단위로 바꾸고, 상태에 따라 경보 색을 나눕니다
// 납기 D-Day 계산 function getDaysLeft(dueDate) { return Math.ceil( (new Date(dueDate) - new Date()) / 86400000 ); // 86400000 = 1일(밀리초) } // 납기 상태 판별 function getDueStatus(wo) { if (wo.status === 'done') return 'completed'; const d = getDaysLeft(wo.dueDate); if (d < 0) return 'overdue'; // 납기 초과 🔴 if (d <= 3) return 'warning'; // D-3 이내 🟠 return 'normal'; // 정상 🟢 }
💡 86400000ms = 1일. 날짜 두 개를 빼면 밀리초 차이가 나오므로 하루(86400000)로 나눠 "남은 일수"로 변환합니다.

핵심 기술 ⑤ — 상태 필터 & KPI 카드

STATUS_META 하나로 라벨·색상·필터를 동시에 관리
const STATUS_META = { waiting: { label: '대기', color: '#64748b' }, progress: { label: '진행중', color: '#0ea5e9' }, inspect: { label: '검사중', color: '#d97706' }, done: { label: '완료', color: '#059669' }, hold: { label: '보류', color: '#dc2626' }, };

KPI 카드 5종

전체 / 진행중 / 검사중 / 완료 / 납기지연 건수를 카드 상단 색상 라인으로 구분해 표시합니다.

필터 버튼 클릭

filterStatus(status)가 currentStatusFilter를 갱신하고 renderCards()를 다시 호출해 카드 목록을 즉시 좁힙니다.

납기 지연 판정: wo.status !== 'done' && wo.dueDate < today — 완료되지 않았는데 납기일이 지났으면 지연으로 집계

핵심 기술 ⑥ — 신규/수정 모달 재사용 패턴

등록 폼과 수정 폼을 따로 만들지 않고 editId 하나로 분기합니다
1

editId로 모드 구분

editId = null이면 신규 등록, 값이 있으면 수정 모드입니다.

2

폼 초기화

openModal(id)에서 id가 있으면 기존 WO 값을, 없으면 빈 값을 폼 필드에 채웁니다.

3

버튼 표시 조건

삭제 버튼은 delBtn.style.display = id ? 'block' : 'none'으로 수정 모드일 때만 보입니다.

4

저장 분기

saveWO()에서 editId가 있으면 배열 항목을 교체, 없으면 push()로 새로 추가합니다.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

POINT 1 — 상태 메타 객체 선행 정의

STATUS_META={waiting, progress, inspect, done, hold}처럼 상태 코드·라벨·색상을 한 객체로 묶으면 카드·필터·KPI에서 일관되게 재사용됩니다.

POINT 2 — 계산 로직을 수식으로 명시

"진행률=produced÷qty×100", "D-Day=(dueDate-today)÷86400000"처럼 계산식을 직접 쓰면 오차 없는 함수가 생성됩니다.

POINT 3 — 채번 형식을 예시로 제시

"WO-YYYYMM-NNN" 같은 실제 출력 예시를 주면 자동 채번 포맷 오류 없이 의도한 형식이 생성됩니다.

POINT 4 — 공정 단계를 순서대로 나열

8단계 공정명을 순서대로 나열하면 버튼 순서·진행률 계산이 나열한 순서 그대로 생성됩니다.

🗂️ "화면이 하얗거나 스타일이 안 먹어요"

index.html · style.css · script.js 3개 파일이 같은 폴더에 있는지, 파일명이 정확한지 확인하세요.

💾 "고쳤는데 화면이 그대로예요"

수정한 모든 파일을 저장(Ctrl+S)하세요. 탭 이름 옆 ● 표시는 저장 안 됨 표시! 저장 후 브라우저 새로고침(F5).

📅 "D-Day나 진행률이 이상해요"

납기일·착수일 형식이 YYYY-MM-DD인지 확인하세요. 날짜 형식이 다르면 계산이 어긋납니다.

⏸️ "zoo code이 멈춰서 아무것도 안 해요"

파일을 만들거나 고치기 전에 승인(Approve)을 기다리는 중입니다. zoo code 채팅창의 승인 버튼을 눌러주세요.

🤖 만능 해결법: 오류 메시지나 이상한 화면을 그대로 복사(캡처)해서 AI에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요. 대부분 해결됩니다.

AI 프롬프트 작성 요령

작업지시서 관리 앱을 한 번에 완성하는 핵심 지시 구조
1

데이터 구조 명시

"WO 객체는 id, no, customer, product, qty, produced, dueDate, status, currentStep 필드로 구성해줘"처럼 필드명을 구체적으로 제시하면 원하는 구조가 그대로 생성됩니다.

2

계산 로직을 수식으로 설명

"진행률 = 생산완료수 ÷ 지시수량 × 100", "D-Day = (납기일-오늘)/1일(ms)"처럼 계산식을 명시하면 정확한 함수가 생성됩니다.

3

예시 값을 함께 제시

"지시번호는 WO-202606-001 형식"처럼 실제 출력 예시를 주면 포맷 실수가 줄어듭니다.

4

기능을 번호로 나열

1, 2, 3... 번호를 매겨 요청하면 AI가 빠뜨리지 않고 순서대로 구현합니다.
